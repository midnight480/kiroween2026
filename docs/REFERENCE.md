# Resource reference

> **Generated** from the mapping tables in `src/mapping/` by `npm run docs:reference`. Do not edit by hand: `npx vitest` fails if this file is out of date.

46 AWS resource types can be written in COBOL: 40 from a table, and 6 with hand-written code (the S3 bucket, the IAM role and managed policy, the Lambda function, and the DynamoDB table and global table). A property name or enum in a table is checked against the official CloudFormation schemas bundled with cfn-lint, so this reference and CloudFormation agree.

For a walk-through, start with [GUIDE.md](GUIDE.md).

## How to read this

Each resource is a `01` group in `WORKING-STORAGE`. Its first item sets the type, and the other items set properties:

```cobol
       01  MAIN-VPC.
           05  RESOURCE-TYPE    PIC X(13) VALUE "AWS::EC2::VPC".
           05  VPC-CIDR         PIC X(11) VALUE "10.0.0.0/16".
```

The group name becomes the logical ID in PascalCase (`MAIN-VPC` is `MainVpc`). Item names are exactly as listed here, in upper case. A misspelled item is an error with a "did you mean" hint; it is never ignored.

**Types**

| Type | What to write |
|---|---|
| text | a string literal |
| number (`PIC 9`) | a numeric item (`PIC 9(n) VALUE 80`) |
| number | a numeric item; CloudFormation receives it as a string |
| `"Y"` or `"N"` | `Y` or `N` |
| name or ID (`REF:` / `GETATT:` allowed) | `REF:NAME` for another resource in this file, `GETATT:NAME.ATTR` for an attribute (`ARN` becomes `Arn`), or a literal ID |
| comma-separated list | values separated by commas, each of which may be a `REF:` or `GETATT:` |
| text (`SSM:` / `SECRET:` allowed) | `SSM:/path` becomes `{{resolve:ssm:/path}}`, `SECRET:id` becomes `{{resolve:secretsmanager:id}}`, anything else is used as is |
| script (`\n` is a newline) | a script as one string; write `\n` for a newline. It is wrapped in `Fn::Base64` |
| `SECRET:` or `SSM:` only | `SECRET:` or `SSM:` only. A plain-text password is an error |
| comma-separated list of targets | ids separated by commas |

Every resource also accepts these items:

| Item | Becomes | Notes |
|---|---|---|
| `DEPENDS-ON` | `DependsOn` | the name of another resource in the same file, or several separated by commas |
| `DELETION-POLICY` | `DeletionPolicy` | `Delete`, `Retain` or `Snapshot` |
| `NAME-TAG` | a `Name` tag | only on resource types that take tags (marked below) |

### AWS::IAM::ManagedPolicy

The statements are an `OCCURS` table. Name the group anything (for example `STMT`); each statement has three items whose names **end in** `-EFFECT`, `-ACTION` and `-RES`. Fill them with `MOVE` and a subscript:

| Item (suffix) | Becomes | Type | Required |
|---|---|---|---|
| `...-EFFECT` | `Effect` | text (`Allow` or `Deny`) | yes |
| `...-ACTION` | `Action` | text | yes |
| `...-RES` | `Resource` | text. `REF:NAME` becomes the **ARN** of that resource, and `REF:NAME/*` becomes the ARN plus `/*` | yes |

Rules:

- Error `MISSING-PROPERTY`: a statement is missing its effect, action or resource.
- Error `SUBSCRIPT-OUT-OF-RANGE`: a `MOVE` uses a subscript beyond the `OCCURS` count.
- Warning `WILDCARD-ACTION`: an action is `*` or ends in `:*`.

### AWS::DynamoDB::Table and AWS::DynamoDB::GlobalTable

A table is a COBOL indexed file: `SELECT` plus `FD`.

| COBOL | Becomes |
|---|---|
| `SELECT ORDERS-FILE ASSIGN TO "DYNAMODB"` | `AWS::DynamoDB::Table` (one region) |
| `SELECT ORDERS-FILE ASSIGN TO "DYNAMODB-MRSC"` | `AWS::DynamoDB::GlobalTable` with `MultiRegionConsistency: STRONG` (multi-region strong consistency) |
| `ASSIGN TO "DBLINK"` | Error `DBLINK-RETIRED`. On purpose. |
| `ASSIGN TO "AURORA-DSQL"` | Error `UNSUPPORTED-IN-MVP` (a stretch goal) |
| `RECORD KEY IS ORDER-ID` | `KeySchema` (HASH) and an attribute definition |
| `ALTERNATE RECORD KEY IS ORDER-STATE WITH DUPLICATES` | a global secondary index named `order-state-index` |
| record item `PIC X(n)` / `PIC 9(n)` | attribute type `S` / `N`. Only key items get an attribute definition |

Billing is always `PAY_PER_REQUEST`.

For `DYNAMODB-MRSC`, add a working-storage group named `<FILE>-REGIONS` (for example `ORDERS-FILE-REGIONS`) with three text items:

| Item | Becomes |
|---|---|
| `REPLICA-1` | the first replica region |
| `REPLICA-2` | the second replica region |
| `WITNESS-REGION` | the witness region (a third region) |

Rules:

- Error `DUPLICATE-REGION`: the three regions must all differ.
- Error `STACK-REGION-NOT-A-REPLICA`: the primary region (`OBJECT-COMPUTER`) must be `REPLICA-1` or `REPLICA-2`.
- Warning `REGION-SET`: a region is outside the AP region set (Tokyo, Seoul, Osaka). MRSC only works inside one region set.
- Without `OBJECT-COMPUTER`, the primary region falls back to `REPLICA-1` (MRSC only).
